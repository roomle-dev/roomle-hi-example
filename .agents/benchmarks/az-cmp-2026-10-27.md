Affected repositories:

- **roomle-hi-example:** the reports of the Azure series, this unnumbered comparison and the indexes.
- **roomle-ui:** the planner and the embedding-lib measured per report; in 06 proposal A, `get-skill` serving a room skill with its planning reference; in 07 the plan state supplied per turn by the planning assistant, with the system prompt naming it as the state before the first change; in 08 the planning assistant's library read before the first prompt, embedding-lib code only; in 09 the two-level attribute section of the planner (D122), web-sdk code only.

This is the single unnumbered comparison of the Azure series. The OpenAI series 01–05
([its comparison](iklw-oa-rc-cmp-2026-10-26.md)) is the same model on direct OpenAI; its turns are
compared with this series for the shape of a turn — the calls and what each one does —, never for
the seconds. The baseline of the seconds on this deployment is the test session of 2026-10-27, one
run per test on the planner of bo-test, so a difference beyond the spread of two repetitions is a
finding, a smaller one is not.

## Decision

**Proposal A is accepted.** Every run of 06 creates at call 2 and none fetches the planning reference apart; the image kitchen comes 6.7 s earlier than the session's run on this deployment, the text kitchen 1.4 s earlier in the mean of two runs, within their spread (28.3–32.3 s, of which the planner's create tool took 3.3 and 8.1 s); the reasoning of the reference round shows up in the create calls (219 / 330 and 319 / 332 reasoning tokens). The kitchens are those of benchmarks 04 and 05 and of the test's expectation. roomle-ui e8964c3df on `feat/hi-mcp-performance` stays.

**The plan state per turn is accepted.** In 07 no model call reads the live sections before the first change of a turn: the move comes in the first call, 7.2 s earlier in the mean than on the build of 06 and in both runs earlier than the faster baseline run (3.5 / 4.5 s against 8.3 / 14.2 s), with two model calls instead of four and half the input tokens; the creations fetch their skill at call 1 and create at call 2 as in 06, within its spread, with the same kitchens. The state costs 4.8–12.1 KB per turn, read in parallel with the library reference. roomle-ui d06fe91de on `feat/hi-mcp-performance` stays, published as `@roomle/embedding-lib@0.0.0-dev-d06fe91`. What remains before the first attempt of a creation is the create call itself — 23–31 s here, more than half of it the wait for its first output, which proposal C addresses — and the skill round, which only the selector of G would take.

**The library read before the first prompt is accepted.** In 08 every page reads the planner's library context once the catalog has loaded and before the prompt, 729–754 ms in the planner; the first turn's library read then takes 6.3–8.4 ms and the first request leaves 0.033–0.045 s after the turn start, against 755 / 781 ms and 0.783 / 0.809 s in the cold checks on the build of 07 — the 0.8 s the hosts paid on the first prompt of a page. The page is ready after 4.9–5.9 s, within 06's 5.0–7.7 s; the plan's groups are reported 0.27–0.34 s after the read on every page, a possible delay six pages do not separate from the spread. The creations keep the shape and the kitchens of 06, their first kitchen within 06's spread. roomle-ui 1b4351d96 on `feat/hi-mcp-performance` stays, published as `@roomle/embedding-lib@0.0.0-dev-1b4351d`; the compacted library context kept in the planner stays rejected — it would save about 5 ms per read, not the templates.

**The two-level attribute section meets the criteria of the analysis, and with the corrected sink descriptions it has no measured cost.** In 09 every creation creates at call 2 with nothing looked up before it, every request carries 8,533 input tokens less, the create calls are 7.0 s (image) and 4.3 s (walnut) shorter in the mean, the kitchens have the looks of the baselines, and the sink stands clear of the hob in all four runs. The handle colour of the image kitchen costs one lookup round after the kitchen, where the baseline spent its round on the backsplash. roomle-ui 5fd409e84 on `feat/hi-mcp-performance`, merged into `feat/hi-mcp-merge` as 4415cdffd, stays; the acceptance of D122 is the user's.
