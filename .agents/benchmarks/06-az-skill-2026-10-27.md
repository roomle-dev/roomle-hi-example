## How it was measured

The collector of report 05, regenerated from the current [prompt runner](../scripts/run-hi-mcp-prompt.js): in the example page, the hook marks every fetch whose path ends in `/v1/responses` (start, response headers, the end of the stream read through a clone, request bytes, the `reasoning` object of the body), the tool bridge `callExternalObjectAgentTool` (start, end, result bytes) and every output part the window receives; in the planner frame, it wraps the seven planner methods of `window.RoomlePlanner` and timestamps the `[hi-mcp]` log lines. Turn start and end are taken around `onPlanningAssistantPrompt`. All marks are `performance.timeOrigin + performance.now()`. No response routing is used, so the browser's HTTP cache works as usual.

A hook check before the paid runs sent the image turn with an invalid key: the bootstrap tool, its planner call and the log lines were timed, and the one model request to the Azure endpoint — 604,455 bytes, no `reasoning` object — was rejected with HTTP 401, without inference.

All four paid runs completed without provider or chat errors, retries or snapshot failures; no run is excluded. The backsplash calculation failure of the image runs is tool feedback, separate from chat success.

## How to read the step deltas

Start/End are seconds relative to the assistant turn start. Delta is elapsed time, rounded to three decimals; the elapsed-ms columns keep short calls. A model call ends when its response stream ends, measured through the clone; its start is that end minus the SDK's response duration, so the start is derived. Model duration includes transport, provider work and streaming. Tool wall time is the union of parallel intervals. A nested planner call belongs to the tool of the last `[hi-mcp] tool` line before its own `[hi-mcp] call` line in the planner frame. Planner calls without such a line are the planner's own price refresh after a plan change, listed apart. A window update is any output part the window receives: a status (`activity`) or a piece of answer text. Runner start follows browser launch; subprocess time includes launch and shutdown.
